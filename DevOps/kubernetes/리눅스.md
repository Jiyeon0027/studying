## 리눅스

### 리눅스 네임스페이스 
프로세스를 실행할떄 시스템의 리소스를 분리해서 실행할 수 있도록 도와주는 기능
(기본적으로는 1번 프로세스의 네임스페이스를 공유해서 실행함)

- 규칙
    - 네임스페이스 안에서의 변경은 내부 프로세스에서만 보이고, 다른 프로세스에서는 보이지 않는다
    - 네임 스페이스와 관련된 프로세스는 부모 자식의 특징을 갖는다.
        - 모든 프로세스들은 네임스페이스 타입별로 특정 네임스페이스에 속한다.
        - 자식 프로세스는 부모 프로세스의 네임 스페이스를 상속받는다.
    - 격리하는 자원에 따라 다양하게 구분되어 있다.

- 네임스페이스 종류
    - cgroup (control group): 프로세스에 할당된 시스템자원에 대한 제어를 제공함.
        - 파일 시스템 기반으로 특수한 파일시스템에서 디렉터리를 만드록 파일을 수정하는 방식으로 설정하고 관리
        - cgroup 네임 스페이스를 이용해 컨테이너가 속한 cgroup만 보이게 한다.
        - 디렉토리 각 항목은 subsystem이라고 한다
        - `tree -L 1/sys/fs/cgroups`
        - 호스트의 하드웨어 자원을 그룹별로 관리하는 모듈 ( CPU, Memeory, Network, Disk IO, Devices ... )
    - ipc(inter process communication)을 지원하는 pipe, message queue, shared memeory, socket 등 다양한 자원이 존재함
    - 네트워크
    - 마운트 : 마운트 포인트를 격리하여 호스트 파일 시스템에 영향을 주지 않고 컨테이너 전용 파일 시스템을 구성할 수 있도록 한다.
        - `unshare --mount /bin/bash` : 마운트 네임스페이스를 격리하여 bash 실행
    - pid : 프로세스 id를 격리할 수 있는 네임 스페이스 (보통 init 프로세스는 1부터 시작하며 이보다 큰 pid를 제공받지만 다른 네임스페이스의 경우 1부터 시작)
    - UTS(unix time sharing) : 호스트 네임과 nis 도메인 이름을 격리하는 네임 스페이스
    - 사용자
        - 컨테이너를 루트 유저로 실행하는 것은 보안상 매우 위험하므로 user 네임스페이스를 이용하면 호스트에서 권한이 최소화된 일반유저이지만, 컨테이너 안에서 루트 유저로 부여할 수 있음
        ```
        <USER 네임스페이스는 uid, gid의 number space를 격리한다는 것을 보여주는 예시>
        컨테이너 터미널
        - id uid=0(root) groups=0(root)
        - exit
        호스트 터미널
        - id uid=1000(vagrant) gid=1000(vagrant) groups=1000(vagrant)
        unshare로 USER 네임스페이스를 격리한 상태에서 컨테이너 id 확인하기
        - unshare —user /bin/bash
        - vagrant@ubuntu1804 → nobody@ubuntu1804
        - id 출력을 확인하면 컨테이너의 uid와 호스트의 uid가 다르다. 다른 USER 네임스페이스를 사용하기 때문이다.
        - 컨테이너를 일반 유저(vagrant)로 실행하면 UTS 네임스페이스를 만들 수 있는 권한이 없다.
        ```

### chroot로 컨테이너 이해하기
Change Root Directory, chroot 에 갇힌 프로세스는 현재 디렉터리를 루트로 인지하여 동작
- 새로운 루트 경로를 만들고 실행할 커맨드와 의존성 라이브러리를 새로운 경로에 복사하여 새로운 경로에서 커맨드를 실행함
- 한계
